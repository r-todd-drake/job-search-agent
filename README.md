# AI Job Search Agent

![Tests](https://github.com/r-todd-drake/job-search-agent/actions/workflows/test.yml/badge.svg)

A working demonstration of grounded, human-in-the-loop LLM pipeline design for a context
where hallucination is unacceptable: representing a real person's career to real employers.
Every generated claim is traceable to a confirmed source library, every output passes
automated quality gates, and a human approves every stage before anything leaves the machine.

**Running it yourself?** The full setup guide, daily workflow, and per-phase CLI reference
live in **[USAGE.md](USAGE.md)**.

## Why It's Built This Way

Most LLM resume tools fail in the same place: they invent experience. This system is
designed around that failure mode.

**Hallucination control**
- **Library-grounded generation** – resumes, cover letters, and interview prep draw only
  from a structured experience library parsed from confirmed career history; the model
  selects and adapts, it does not invent
- **Two-layer quality gates** – `check_resume.py` and `check_cover_letter.py` run
  deterministic string rules (banned terms, lapsed certifications, gap language) plus an
  API-based semantic assessment for implied claims the rules cannot catch
- **Staged human review** – four-stage generation workflows with an explicit human
  approval file between draft and document; stage files are the source of truth
- **No auto-send, anywhere** – outreach and applications are produced to the terminal and
  submitted by the human; the pipeline never acts on the outside world by itself

**Engineering rigor**
- **Two-tier test suite** – 560+ mock tests run in CI on every push; a separate live-API
  tier gates phase promotion
- **Prompt-content regression tests** – every prompt guardrail has a test asserting the
  content it references is actually present in the assembled payload, not just that the
  instruction wording exists; added after a live defect where a confirmed-skills guardrail
  shipped against content a hardcoded truncation had already removed
- **Modular shared libraries** – parsing, PII filtering, candidate config, and domain
  config are importable modules with injectable dependencies for testability
- **PII firewall** – `pii_filter.py` strips personal identifiers from every API call;
  personal data lives in gitignored config, never in code
- **Single-source documentation** – this README, USAGE.md, and the project context doc
  are assembled by `build_docs.py` from shared fragments so operational facts cannot drift

## Architecture at a Glance

A phased pipeline: rank incoming roles, generate tailored application packages from a
grounded experience library, prepare for interviews stage-by-stage, capture structured
debriefs, and run warmth-calibrated networking outreach – with a human decision point
between every automated step.

## Security & Privacy by Design

PII is stripped from all API calls before any data leaves the local machine.
`pii_filter.py` loads scalar PII values from `.env`; structured career data
(education, certifications, military history, confirmed gaps, etc.) is stored in
`context/candidate/candidate_config.yaml`. Neither file is hardcoded in the published code.

All personal data (experience library, resumes, job packages, tracker, career config,
and candidate background files) is excluded from version control via `.gitignore`.

Anthropic API: inputs are not used for model training under commercial terms.
